# ADR-0001: Retrospective Architectural Decisions

**Date:** 2024-12-13

**Status:** Accepted

## Purpose

This document serves as a placeholder for documenting architectural decisions that were made before the ADR process was established.

## Instructions

When documenting past decisions retroactively:

1. Create a new ADR file using the template in `0000-adr-template.md`
2. Use the date the decision was originally made (or your best estimate)
3. Mark the status as "Accepted" since these decisions are already in effect
4. Document the context as you remember it, noting any uncertainty

## Decisions to Document

Consider creating retrospective ADRs for decisions such as:

- [ ] Choice of React + Vite for frontend
- [ ] Choice of Express + Prisma for backend
- [ ] PostgreSQL as the database
- [ ] Google OAuth for authentication
- [ ] JWT-based session management
- [ ] Monorepo structure with shared types
- [ ] CodeMirror 6 for the editor
- [ ] WebGL for shader rendering
- [ ] Docker-based development environment
- [ ] Vercel + Railway deployment strategy
